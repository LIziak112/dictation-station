# better-interface 界面复查

## 范围与覆盖

2026-11-03，按用户要求在功能实现后执行 better-interface 及其六个领域技能。范围为今日任务→安排→听写→核对的主流程、全局导航、词库、纯听和跟读入口。React 19、原生表单／details、Lucide 图标和现有 CSS 语义变量；未新增 UI 库、字体或 CDN。仓库没有独立 AGENTS／CONTRIBUTING／设计系统文档；产品约定来自《听写小站开发计划》。这次是产品界面优化，不是 PR 差异审查。

| 领域          | 检查证据                                                                                                                            | 结果                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Accessibility | Portal、Session、TaskEditor、TaskPlayer、TaskReview、ListeningPractice；原生控件名称／焦点样式、键盘 Enter 导航、切页焦点与保稿测试 | 已修复主流程切页标题、正文焦点和返回保护                         |

## 发现与修复

以下位置指修复后的入口，Before 为检查时的实现；全部已修复。

| 严重度 | 领域          | 位置                                           | Before                                                           | After                                                                     | 原因                                         |
| ------ | ------------- | ---------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------- |
| HIGH   | Writing       | apps/web/src/Today.tsx:18                      | 初始空数组立即显示“还没有安排任务”；失败仅显示错误               | 独立加载状态、稳定 status 区域、明确重试按钮；失败不冒充空库              | 加载失败不能误导成没有任务                   |
| HIGH   | Colors        | apps/web/src/style.css:17、FocusControls.tsx:9 | 深色文字仍叠在浅色 hover／账号表面；主题过渡会短暂混色           | 复用主题语义变量，切换时关闭过渡                                          | 修复深色可读性与主题状态不一致               |
| HIGH   | Accessibility | apps/web/src/Portal.tsx:83                     | 仅按钮导航保稿，直接 hash 切换绕过保护                           | hash 切换同样检查保稿事件；失败恢复原地址并保留编辑器                     | 浏览器导航不能丢失未落盘内容                 |
| MEDIUM | Layout        | apps/web/src/style.css:173、1180               | 账号、导航和工具挤在一行，按钮在桌面被压成多行；专注菜单缩成窄条 | 品牌／工具一组，主导航独立一行；账号收进有提示的 disclosure；菜单明确宽度 | 实际截图确认可读性受损，修复后窄屏无水平溢出 |
| MEDIUM | Accessibility | apps/web/src/Portal.tsx:56、TaskPlayer.tsx:35  | 主要新页面不更新标题与焦点，键盘用户留在旧导航                   | 切页更新标题、聚焦 main；任务异步读取后恢复正文焦点；可跳到正文           | 页面变化需要可感知且可继续操作，WCAG 2.4.3   |
| MEDIUM | Layout        | apps/web/src/Portal.tsx:95                     | 记录等页面刷新回到旧任务／首页                                   | 主导航页面使用明确 hash，并标注当前页面                                   | 保持位置和操作反馈一致                       |
| LOW    | Typography    | apps/web/src/style.css:1276                    | 跟读长句与数字沿用普通标题默认值                                 | 自适应字号、长句换行、动态计数等宽数字                                    | 提升句子和进度的可读性                       |

## 验证

- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。
- `pnpm exec playwright test e2e/ui-polish.spec.ts --project=chromium`：3 项通过，覆盖窄屏／双倍字号／刷新／焦点、读取失败重试、hash 保稿、主题。
- `pnpm exec playwright test e2e/listen.spec.ts --project=webkit`：2 项通过；麦克风与语音使用明确合成替身，不访问实际麦克风。Chromium 同一组 2 项通过。
- 任务接力、账号隔离和原有 interface 用例相关 Chromium 回归通过。PNG 汇报卡和拼音打印纸此前已实际查看。
- 已实际查看 320／1280px 今日页和深色专注菜单截图；宽度断言也覆盖 768px。没有用截图代替数据正确性测试。
- 按 CSS 值计算 WCAG 对比：浅色主按钮 7.04:1、深色主按钮 8.18:1、浅色次要文字／面板 5.50:1、深色次要文字／面板 7.18:1、深色控件／表面 12.67:1、深色控件／hover 9.29:1。主按钮另用浏览器实际 computed style 验证 ≥4.5:1；未把所有文本组合声称为完整对比审计。

Not verified：真实读屏软件、iPhone／Android 硬件、原生 200% 浏览器缩放（自动化使用双倍字号和窄屏检查）、系统锁屏／后台音频、打印机输出、原生群聊分享、RTL（本项目目前仅中文）。其余页面做源码检查，不声称每个异常分支都已截图验收。
