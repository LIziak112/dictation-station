# 听写小站开发计划

日期：2026-11-03。状态：用户已确认，已完成全部阶段并升级为双端隔离闭环架构；最新完整架构与状态机契约见 [双端架构与完整功能规范](双端架构与完整功能规范.md)，实施进度见 [实施记录](实施进度.md)。本文记录开发计划与演进依据；此前 TypeScript 重构文档用于了解历史现状，其中公开读取、共享口令、旧数据兼容等约定已由新规范替代。

## 1. 目标与范围

一个账号、一个词库，完成「自带 AI 准备材料 → 家长确认今日任务 → 自主纸笔听写 → 核对 → 待巩固词自动复习」闭环。服务端仍是用户自部署的单个 Node 服务与 SQLite；下文的跨设备同步指同步到这台服务，不额外建设云平台。

明确纳入：

- 简单登录、词库隔离、家长区／孩子区、同账号多设备接力。
- 已有词表勾选或编号范围、追加今日内容、今日任务、历史记录。
- 按练法记录掌握状态、隔日复习、阶段总复习。
- 词书／词典真人音频优先，合成语音兜底，来源与覆盖透明。
- AI 提示词、格式契约、账号 API、本地 MCP 桥接。
- 打印、打卡卡片、轻周报、少看屏幕、纯听、跟读回放。

明确不做：

- 家庭、多孩子档案、角色权限体系、邀请协作、付费体系。
- 旧账号／旧词表／旧浏览器记录迁移及兼容层；开发者自行重建测试数据，不自动删除现有目录。
- OCR、文本解析和照片导入优化；保留现有能力，不新增站内大模型调用。
- 家长录音、音频上传覆盖、自动手写批改、口语自动评分。
- 离线写入同步队列、实时协作、WebSocket、CRDT、消息队列、插件平台、通用规则引擎。
- 多词典自动聚合、无限重试、静默吞错、为未知场景增加兼容分支。

简单实现原则：服务边界做一次 Zod 校验；数据库约束保证归属与唯一性；密码存储、账号隔离、提交去重是业务必需。业务内部使用明确类型和直接调用，不层层重复校验、不抽象尚不存在的第二种实现。新增功能需要的模块再拆分。

## 2. 现状与复用

当前 React/Vite、Hono、Zod、Drizzle/SQLite、Vitest/Playwright 栈继续使用。五种练法、BrowserAudio、Playback、JSON 契约、原图核对、已有词表编辑都复用。

当前缺口：batches 无账号归属；读取公开；WRITE_TOKEN 只有全站写保护；浏览器只保存一份 progress；wrongIds 依附当前词表；没有独立任务、历史、跨词表掌握状态；英语设备朗读固定 en-US；拼音不控制实际发音。

不把这些缺口修补成越来越大的 Progress。新增 Task 和 Attempt，Progress 只承担播放游标和临时核对草稿。

## 3. 页面与完整流程

### 家长区

导航为「今日任务／词库／待巩固／记录」，账号与 AI 连接放设置。记录内包含周报、打印和卡片，不单独增加统计中心。

1. AI 根据任意材料整理，粘贴 JSON 或通过工具存入草稿。
2. 家长核对词义、顺序、拼音与读音，确认保存词表。
3. 从一份或多份词表勾选词语；支持第 1–20 项等编号范围；可通过现有编辑／AI 草稿追加今日内容。
4. 选择练法和日期，默认保持作业原顺序；可加入少量同练法待巩固词。
5. 显示「作业 20 项 + 复习 3 项，预计约 8 分钟」，可点「今天只完成作业」。已有词不一定是新词，文案不统一称“新词”。手动推进下预计时间是估计值。
6. 确认发布任务，孩子设备打开同一账号即可看到；任务链接仍要求登录。

### 孩子区（`?child=1` 独立工作台）

通过家长端生成的 `childToken` 免密二维码／专属链接（`?child=1&ct=ct_...`，首次加载自动抹除地址栏参数并支持一键重置）独立进入孩子听写区，分为 **01 今日听写任务**、**02 批改结果与错词订正**、**03 自主磨耳朵（纯听与跟读）** 三大板块。家长端仅负责派发、监控与批改，不执行学生听写。

服务端通过 Deny-by-Default 白名单中间件严格限制 `childToken` 权限：交卷前物理剥离 `answer`／`alt` 答案字段；存在未完成或进行中任务时，磨耳朵板块自动遮罩待考词的中英拼写文字，仅开放语音播放与跟读，防止提前泄密。完整安全矩阵见 [双端架构与完整功能规范](双端架构与完整功能规范.md)。

## 4. 核心规则

### 4.1 账号

用户名＋密码；注册、登录、退出、修改密码。自部署开关决定是否允许注册。Node crypto.scrypt 存密码哈希，随机会话令牌存摘要；同源 HttpOnly/SameSite Cookie，HTTPS 下 Secure。会话建议保留 30 天。无短信、邮箱验证、社交登录；忘记密码由部署者 CLI 重设并清理该账号会话。

所有词表、任务、记录、待巩固、草稿、音频读取和写入按服务端会话 accountId 查询，客户端不指定数据所属账号。移除旧公开词表与二维码分享；保留本账号任务链接／二维码、JSON 导出和卡片分享。媒体文件不能继续通过通用静态目录公开访问。

### 4.2 词库与内容身份

一个词库包含多份词表。词条 kind 为 character／word／phrase／sentence，展示统一用“项”。保留 en、zh、pinyin、hint、alt、modes，不增加复杂教材层级。

复习不能只用 batch 内位置 ID。账号内词条具备稳定 wordId；词表保存有序条目引用。相同规范化语言内容、词义、拼音、语境提示和读音选择复用词条，不做 AI 相似合并；bank 的不同义项或不同读法保留为不同词条。编辑实质内容产生新的词条身份，避免继承旧掌握结果；同一词条可出现在多份词表。

任务固定保存发布时条目快照、wordId、练法、顺序和实际采用的音频选择。词表后来修改或删除不改变任务／历史，也不删除已有复习数据。内容身份匹配用简单规范化键，不建设词典知识图谱。

### 4.3 今日任务与记录（6 态生命周期）

Task 状态采用 6 态生命周期：`pending（待开始） → in_progress（进行中） → submitted（已交卷待批改） → completed（已批改）` 及 `withdrawn（已撤回） / expired（已过期）`。同一时刻仅允许 1 个任务处于 `in_progress`。进行中任务禁止编辑内容，仅允许二次确认后撤回并保留 `interruptedAt` 中断记录；已交卷任务支持家长一键退回重做（`returnForRedo`）或完成四态批改（`correct` / `wrong` / `uncertain` / `unchecked`），可选开启 `allowSelfReview` 允许孩子自评并随机生成 1–2 个抽查词（`spotCheckWordIds`）。详细状态机见 [双端架构与完整功能规范](双端架构与完整功能规范.md)。

任务发布前可编辑，开始后固定范围与顺序；变更通过复制新任务完成。任务可包含多词表内容，但每份任务只采用一种练法；不同练法创建不同任务，保持播放器和结果简单。

Attempt 表示一次实际练习。第一次开始建立 Attempt，完成后保留；再次练习产生新 Attempt，不覆盖历史。同一 Task 同时只允许一个进行中的 Attempt。进度保存携带 revision；第二台设备要接力时刷新并继续，同步冲突提示重载，不合并两台设备同时输入。

游标切换、暂停、核对操作保存到服务端；打开任务、页面重新可见时刷新。家长任务列表可见时每 15 秒轮询。失败时显示“尚未同步”和重试，临时内容保留本设备；无自动离线重放。退出登录清理账号内存，草稿与未同步进度按 accountId 隔离保留，避免退出丢稿。

完成接口按 Attempt ID 去重：重复点击或重试只完成一次。已完成核对结果不原地修改；订正另存，不重算为一次独立通过，保持规则简单。

### 4.4 待巩固与复习

学习状态键为 accountId＋wordId＋mode。例如 en2en 与 zh2en 独立；不扩张成“听说读写能力模型”。多音词由词条的内容身份区分。

- wrong：加入待巩固，连续通过数归零。
- uncertain／unchecked：不增加通过数、不移除待巩固；允许后续另建核对后的练习。
- correct：首次写对的普通词不额外加入复习；已在复习池的词进入通过计数。
- correction：看答案后订正，单独计数，不算独立通过。
- 默认在 3 个不同日期独立通过后掌握；账号可调整阈值，调整后从下一次合格结果起生效，不追溯重算。
- 日期统一采用账号设置时区，默认 Asia/Shanghai。同日多练最多记一次通过；同日出错仍归零。不同日期才可再次计数，不要求连续三个日历日。
- 同日先错后对视为订正，不计通过；练习时已看答案的该项也不计独立通过。
- 默认下一日可复习，再通过后分别延后 3 天、7 天；阈值超过 3 时后续间隔保持 7 天。不引入记忆算法或科学效果承诺。
- mastered 再错重新入池；允许家长手动移出／恢复，标为手动，不伪造通过记录。

每日混入默认 3 项，可关或调整。只选相同练法、到期、未掌握、且今日作业范围未含的词；先到期先选，同日按最近出错优先，不随机改变候选集。不足则少加，发布后候选固定。

穿插默认每 5 项作业加入 1 项复习，保留作业项相对顺序；剩余复习放末尾。也可选择全部复习放末尾。“今天只完成作业”在开始前移除附加项，已开始后不临时改变计分队列。

阶段复习：家长选择起止日期和练法，以该时间段内练过且当前未掌握的词去重生成预览，可全选／勾选后发布。含待巩固和不确定，明确标签。沿用每任务 500 项上限，超出提示缩小范围，不暗中截断。

### 4.5 核对与周报

默认“只点需要再练的项”，但完成前必须确认“已全部核对，其余正确”。未确认的其余项保留 unchecked。提供 uncertain 和逐项正确，禁止在开始时默认全部正确。

记录详情展示完整序号、题目快照、核对状态、订正情况、音频来源及模式。周报按请求实时聚合：本周完成次数、当前仍待巩固的词、按当前规则下次将选的词。后者标为预览，未发布前会变化。无邮件、推送、定时任务或复杂图表。

## 5. 真人音频

### 实现与优先级

词条指定的真人读音 → 部署时选定来源的匹配真人音频 → 现有服务端 TTS → 设备 TTS。均显示实际来源；无可用声音时提示改用可用来源或重试，不静默跳过该项。家长录音已取消，不新增上传覆盖接口。

第一版只接一个已确认可用的词书／词典来源，并支持部署者提供的、有权使用的本地音频索引：语言、内容、口音、读音标识、文件、来源名称、来源页面。索引格式固定，不建设适配器注册平台。英语与中文分别展示实测覆盖，不承诺同一来源覆盖两种语言。

真人词书名称、教材来源、声音来源分开保存；AI 只能填写教材出处与建议读音，不允许用任意 URL 自动抓音频。中文使用完整词语／句子匹配，不拼接单字录音。read 等异读词和中文多音字必须能选具体读音；未匹配的短语、句子走明确标识的合成音，不虚称真人。

准备页展示“真人 18／合成 5／不可用 0”，逐项试听与英美音选择。先为整份任务解析声音清单，再按来源允许方式预加载和检查文件；不允许缓存的来源仅做获准检查，不下载持久化。设备 TTS 只能检查设备能力，不能承诺所有词都预先播放验证。

发音键包含内容、语言、口音、读音和来源，修正读音后不能继续命中旧音频。切词、暂停、离开时复用现有取消逻辑。TTS 中拼音文本不自动当作读音控制，选用明确支持的读音机制或真人条目。

### 前置小验证与外部条件

实施前用实际来源验证常用英语、中文多音词、短语、句子各一组，记录覆盖、响应、可否预加载与使用条款。选定首个来源后才编写正式适配代码；接入预算／授权和中文覆盖是待落实外部条件，不伪装成已解决。

- [Merriam-Webster 官方入口](https://www.dictionaryapi.com/) 提供音频 API；免费使用有非商业、每日每 Key 1000 次、最多两种参考 API 等限制，不据此推定可任意缓存。
- [Forvo API 条款](https://api.forvo.com/documentation/general-information/) 写明音频链接有效期两小时、禁止缓存，故不预设其能承担整卷预下载，更不将其作为默认音频资源包。
- 新来源先确认获取／播放／缓存方式，并在 SOURCES.md 记录，代码与仓库不附带未经许可的词书音频。

对外文案用“真人发音优先，缺失项明确标注”，不使用“没有机械音”。

## 6. AI 与 MCP

材料理解交给用户自己的 Agent。站内保留现有导入，不做新的拍照流程。完善提示词：保留原顺序、指定今日范围、识别字／词／短语／句子、保留教材词义与拼音、不确定项列出供核对、不要补造教材内容。JSON Schema 由 Zod 导出，不另写第二套约束。

提供账号内 API：获取格式、校验词表、建立草稿、列出／读取自己的词表。Agent 保存后返回家长区草稿链接，网页核对并点击“保存词表／发布任务”才成为正式内容。无模型工具可以写掌握状态、完成任务或读其他账号数据。

令牌为随机 opaque token，服务端存摘要、accountId、scopes、过期时间，用户可撤销。账号归属不要求采用 JWT。首版仅 wordlists:read、drafts:write；不申请记录读取权限。

MCP 首版为本地 stdio 小桥接，环境变量配置服务地址与账号令牌，调用上述现成 API；使用官方 TypeScript SDK，不手写协议。先验收一个明确支持本地 MCP 的客户端。只有远程连接的客户端不在首版支持范围，提供 API／JSON 作为入口。

HTTP MCP 与 OAuth 兼容接入作为后续独立扩展，不自建 OAuth 服务器或做假兼容。[官方授权规范](https://modelcontextprotocol.io/specification/latest/basic/authorization) 区分 HTTP 与 stdio；本地方案避免把远程授权系统塞入简单项目。连接说明明确支持的客户端和配置方法，不能宣称所有 Agent 一键接入。

## 7. 轻量输出与陪练体验

### 打印与打卡

- 浏览器打印页＋@media print，系统另存 PDF；不引入 PDF 服务。
- 三模板：待巩固练习纸、看拼音写词语纸、听写空白纸；带任务标题、日期、编号，答案页独立且默认不打印。句子预留更多行。
- 卡片用 Canvas 绘制并导出 PNG：完成项数、待巩固数、未核对数、订正情况；不是自动批改成绩证明。
- 用户可选择本机书写纸照片绘入卡片，默认不上传、不单独建云相册；刷新后需重选。下载 PNG 为必备，系统支持文件分享时提供系统分享按钮；不做微信／老师群自动发送。

### 大按钮、节奏与专注

- 默认手动下一项；自动模式按基础等待＋文字长度做简单延时，上限与手动设置可调整。中文按字数、英语按词数估算，不训练节奏模型。
- 默认每 5 项为一组，组间提示并休息 10 秒，可立即继续、可关闭分组。小任务不强制分组。
- 连续活动 20 分钟在下一项或组间提示休息，不打断正在播放的词；暂停时间不计。
- 可关闭的简短语音引导；与报词共用播放控制，不叠加播放。图标配文字，核心按钮建议至少 48px。
- 深色／浅色、全屏按钮、投屏友好的宽屏排版；不做独立投屏协议。
- 网页不能锁住系统或禁止离开应用；提供系统引导式访问／屏幕固定的简短设置说明，不做虚假锁定。[MDN 全屏说明](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API/Guide) 明确用户可退出全屏。

### 纯听与跟读

- 纯听：复用词表与真人声音，可选英文、中文或中英交替，循环与顺序播放；不产生听写正确记录、不更新掌握状态。课堂听写仍按既有逻辑后台暂停。
- 纯听后台／锁屏播放仅对目标设备实测后标明支持；前台播放为基础验收，不承诺网页在所有系统后台连续运行。必要时用户获准的音频可另做整段导出，但不列入本轮。
- 跟读：示范播放 → 孩子录音 → 回听／与示范交替播放；仅本机短期保留，离开释放，无评分、识别、上传和云存储。它不作为词条的发音来源，不是被取消的家长录音。
- 麦克风拒绝时仍可听示范；真实手机浏览器验证权限、编码与回放。跟读不参与听写的掌握计数。

## 8. 最小数据结构

全部 schema 先落 packages/contract，再实现服务；accountId 外键及组合唯一索引在数据库约束。具体字段按阶段加入，不先建空壳表。

| 表              | 主要字段／职责                                                                          |
| --------------- | --------------------------------------------------------------------------------------- |
| accounts        | username、passwordHash、timezone、复习偏好                                              |
| sessions        | tokenHash、accountId、expiresAt                                                         |
| words           | accountId、wordId、内容字段、kind、内容身份键、读音选择；账号内身份键唯一               |
| batches         | accountId、title、来源信息、按序 wordId 引用、revision；继续可用 JSON payload           |
| drafts          | accountId、payload、createdAt；Agent 与现有编辑入口共用                                 |
| tasks           | accountId、title、日期、mode、状态、条目快照、作业／复习来源、播放设置                  |
| attempts        | taskId、accountId、游标、核对草稿／最终结果、已揭示答案标记、订正、revision、完成时间   |
| learning_states | accountId＋wordId＋mode 唯一；status、streak、lastQualifiedDate、lastWrongDate、dueDate |
| api_tokens      | tokenHash、accountId、scopes、expiresAt                                                 |

音频索引使用部署文件即可；无单独音频数据库、事件总线或日统计表。家长 PIN 留在本机。结果项目存 JSON 足够，周报先用账号内记录直接聚合，出现真实性能问题再优化。

## 9. 分阶段开发文件、测试与交付

每阶段独立 codex/ 分支，小步提交。以下为已获用户授权的顺序计划。音频来源验证 A 与账号工作 B 的技术依赖独立，但按单人顺序推进即可。

### B：账号、词库归属与私有读取（约 2–3 日）

### C：词条身份、范围与任务接力（约 3–4 日）

## 10. 验证与发布

各阶段按风险先写失败测试再实现，优先新增 auth.test.ts、tasks.test.ts、learning.test.ts、pronunciation.test.ts、mcp.test.ts；复用 core/server/reliability 测试。外部服务测试采用小型合成响应，真实来源另记手测，不让常规 CI 依赖付费 API。

E2E 最少覆盖：注册登录隔离、AI 草稿确认、勾选范围发布、跨浏览器上下文接力、核对完成、混入旧词与仅作业、历史与打印、孩子区答案隐藏。浏览器上下文必须独立，不能用同一个 localStorage 假装跨设备。

实际以本仓库 package.json 为准：开发用 pnpm exec vitest run <相关测试>；合并前执行 pnpm lint、pnpm typecheck、pnpm test、pnpm schema:export、pnpm build、pnpm e2e，由 PR CI 承担可自动化全量。本仓库没有主项目的 affected 选测或 gen:spec，不套用不存在的命令。

涉及 schema 变更执行 pnpm db:generate，提交迁移；JSON Schema 由脚本生成后提交。同步 README、DEPLOY、WORDLIST-SPEC 和新增专题。人工验收列出手机音频、麦克风、打印预览、分享文件、系统全屏等实际结果。

完整 diff 依次做简化审查、正确性审查，再检查账号私有数据与令牌出口；删掉过早抽象，修复已确认问题。测试失败或外部音频未落实时如实记录，不能宣布该阶段完成。

本计划粗估约 18–26 个开发日，加首次组合验收与修正约 2–3 日；授权等待不计。按实际验证调整，不作为交付承诺。B–F 构成核心闭环，G–H 为后续独立交付，避免一次大 PR。仓库发布基线和目标分支由实际分支配置确定，不把另一个项目的 v2→main 流程强加到本仓库。
