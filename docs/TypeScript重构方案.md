# 听写小站 TypeScript 重构方案

## 目标与边界

将验证项目改为可维护的独立听写工具，为 OwnClass 关联预留清晰契约。本轮在 dictation-station 内完成，不修改主项目、不部署、不合并 PR。不新增学生账号、在线笔迹、自动判分或大模型代调用。

保留五种听写模式、纸笔作答、人工核对、错词重练、旧分享链接 `#batch=...`、`/tingxie/` 子路径，以及未配置 WRITE_TOKEN 时的开放使用。开放读取包含完整词表，定位为练习工具，不是考试接口。接入 OwnClass 时必须重新设计受权限控制的学生公开投影，不能直接复用本接口。

## 文件与分层

- `packages/contract/src/index.ts`：Zod 词条、批次、请求、语音及本机进度契约，输出类型从 schema 推导。
- `packages/core/src/`：导入解析、模式投影、词条检查、词级读音提醒、播放器状态与取消控制；不依赖 DOM 或数据库。
- `apps/server/src/`：Hono 路由、Drizzle/SQLite 存储、旧 JSON 导入、OCR/TTS 适配与限流；只有服务端持有外部凭据。
- `apps/server/drizzle/`：drizzle-kit 生成的迁移；启动执行迁移。
- `apps/web/src/`：React 工作台、导入/编辑、播放与核对、本机草稿/会话、请求层、移动端样式。
- `test/`、`e2e/`：契约/解析/存储/接口/播放器测试、浏览器完整流程。
- 根配置：pnpm、TypeScript strict、Vite、Biome、Vitest、Playwright、CI；README、DEPLOY、WORDLIST-SPEC 同步。

## 实施顺序

1. 工程地基：先提交方案；建立可复现依赖与标准命令。先补失败测试，保留已有 OCR 表格解析和公开播放回归。
2. 契约与服务端：严格校验字段、长度、模式需求与唯一 ID；写入事务完成后返回成功。SQLite 首次导入旧 `data/batches.json`，事务失败不写导入标记、不删除旧文件；坏文件显式阻止启动，不当作空数据。更新携带 revision，拒绝覆盖其他设备的新版本。
3. 前端：主页搜索与词表管理；普通文字/JSON/文件导入；原图本机预览与 OCR；可选复制 AI 提示词；移动端逐词编辑；导入/编辑草稿保留，存储失败明确阻止无提示离开。
4. 听写：先配置范围、模式、顺序、重复和间隔；设备朗读默认不请求付费 API；可选服务器预生成音频，展示准备/失败/重试与逐词试听。任何停止、切词、离开、后台或旧异步回调都不能继续串音。无音频模式手动切词。按词条稳定 ID 保存进度、自评与错词，恢复时检查词表 revision。
5. 内容关联：版本化 JSON 导入/导出；旧分享链接可用，二维码本地生成；公开分享只影响链接，不携带管理口令或源图；批次读取剥离 OCR 原文。主项目账号、课程布置、跨设备记录作为后续专题，不假装本轮已接入。
6. 质量闸门：先简化审查，再正确性审查，再检查公开载荷/凭据/外部调用边界；修复发现的问题后再提交 PR。

## 测试与验收

- 解析：原 OCR HTML 夹具、普通中英/拼音、带代码围栏 JSON、无效结构、空/超长/重复 ID、模式缺字段、无静默截断。
- 持久化：成功写后立即重启仍存在；旧文件导入、重复启动不重复导入、损坏文件阻断、更新冲突/删除、失败事务不污染数据。
- HTTP：可选口令每个写接口保护、公开读取不含 sourceText/凭据、无效请求返回 400、分页/错误状态、同源安全、限流；OCR/TTS 使用合成适配器不调用真实外部服务。
- 播放：立即播放、重复、间隔、停止、切词、自然结束、失败、陈旧回调、后台暂停、拼音模式静音、速度、随机顺序恢复。
- E2E：创建→修改→导出→分享→播放→核对→错词重练；刷新恢复、坏本机稿不被覆盖、网络失败保留稿、320px 与桌面无水平溢出、键盘可达。
- 命令：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm e2e`（Chromium/WebKit）；CI 同样执行。不调用主项目的选测脚本，因为本仓库没有它们。
- 真机边界：浏览器模拟不能证明 iOS 自动播放、系统后台行为、多音字实际发音、手机键盘和扬声器效果，PR 列出人工验收步骤。

## 部署与回退

Node 24+、pnpm 安装/构建，`node server.js` 保留为构建后入口；DATA_DIR 可配置，默认仍为根 data。Python edge-tts 仅服务器语音可选。先停旧服务并备份整个 data，再启动新版本；回退必须恢复旧程序与对应旧数据备份，不能声称 SQLite 新写内容自动回写 JSON。子路径由 BASE_PATH 配置，根路径和子路径共用相对 URL。独立入口的 Service Worker 路由冲突须由主站修复或使用独立子域，本项目不修改主站线上 SW。

## 依赖说明

React/Vite/TypeScript、Hono、Zod、Drizzle/better-sqlite3、Vitest/Playwright/Biome 与 OwnClass 栈一致。二维码复用 qrcode npm 包并随构建打包，不使用 CDN。暂不引入第二套路由/全局状态/查询框架，当前页面范围用 React 原生状态和 hash 深链接即可；可在进入主项目时接入已有路由与查询层。CSS 使用本项目语义 token，不复制主项目所有组件与依赖。
